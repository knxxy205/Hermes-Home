## Rendering changes

The former navigation effect recorded the whole page a second time using Backdrop, then used separate blur/refraction pipelines for the bar and moving indicator. Each scrolling screen could invalidate that recording. This implementation removes the page recording and the Backdrop dependency. The navigation keeps its capsule, translucent surface, light edge, moving selection, press feedback, icon transitions and spring settling, using ordinary Compose drawing and layers. It no longer refracts live page content. The subtle vertical surface tint separates the glass edge from the body without needing a full-page texture or runtime shader.

The indicator now reads the current pointer position directly in its graphics layer during a drag. Drag updates no longer restart an `Animatable` spring for every pointer event. The spring runs after release or cancellation. A drag still commits a destination only after release, cancellation restores the current destination, RTL mapping remains, and Android's disabled-animation preference is respected.

File sections are partitioned once per changed list. Rows and section headers have separate lazy content types, row date and size labels are cached, and file cards use their existing border without a separate elevation shadow per row. The file list is isolated from transfer status rendering. Settings preference cards are separate lazy items instead of one tall eagerly composed item. Chat rows, model rows and transfer rows have explicit content types; model filtering and transfer dates are cached. Markdown patterns are compiled once and formatted table cells are remembered.

## Terminal and keyboard

Terminal history now scrolls by pixels, including fractional row offsets, instead of advancing only in whole text rows. Dragging and flinging preserve partial-row movement and each session's viewport. Selection hit testing, handles and action-mode coordinates include the offset. The renderer visits only the rows needed for the visible viewport, including the partially exposed row.

Keyboard and navigation clearance now use the greater of the animated IME inset and the measured navigation height. Insets are read in layout through `windowInsetsPadding`, avoiding a sudden loss of navigation padding on the first keyboard frame and avoiding recomposing the page for each inset value. The navigation hides while the keyboard is visible, as before. All four page compositions and SSH service ownership are retained.

Terminal size changes are posted to the next display frame. The session coalesces size requests for 100 ms on its existing IO scope. This replaces two consecutive 180 ms delays while keeping emulator reflow and PTY updates out of the UI callback. A resize burst still applies its final size and retains output.

## Refresh rate and APK

The Activity requests the highest supported display mode at the current physical resolution, setting both its mode ID and preferred refresh rate. A device offering 120 Hz at that resolution can therefore select 120 Hz without an application-side 60 Hz cap or a resolution switch. Compose animations and native terminal invalidation use the display's frame clock. Android, battery settings, thermal policy and the device determine the actual selected rate; 120 FPS is not claimed as measured.
